Dominando Ponteiros, Recursão e Gerenciamento de Memória

1. Ponteiros e a Relação com Arrays

Um conceito crucial: O nome de um array é, na verdade, um ponteiro constante para o seu primeiro elemento.

Array: int vet[4] = {10, 20, 30, 40};
10
vet[0]
20
vet[1]
30
vet[2]
40
vet[3]

Ao fazer *(vet + 1), você acessa o valor 20.

Ponteiro para Função

Sim, é possível apontar para uma função! Isso permite passar funções como argumento para outras funções.

void (*ptr_func)(int);

Aritmética de Endereços

Subtrair dois ponteiros (p2 - p1) resulta no número de elementos entre eles, não na distância em bytes.

2. Recursividade e a Pilha do Sistema

Toda vez que uma função recursiva é chamada, o sistema reserva um espaço na Pilha (Stack) para os dados daquela chamada.

⚠️ Estouro de Pilha (Stack Overflow):

Ocorre quando a recursão é profunda demais ou o caso base nunca é atingido, consumindo toda a memória RAM reservada para o programa.

✅ Recursão em Cauda (Tail Recursion):

É um tipo especial onde a chamada recursiva é a última coisa que a função faz. Compiladores modernos conseguem otimizar isso para não gastar memória extra.

Recursividade vs Iteração

Critério Recursividade Iteração (Loop)
Código Mais limpo/elegante Mais extenso
Memória Alta (usa Stack) Baixa

3. Perigos de Memória (Cuidado!)

Ponteiros são ferramentas perigosas. O PDF cita cuidados essenciais que caem em provas:

  • Ponteiro Solto (Dangling Pointer): Acontece quando você tem um ponteiro para uma variável que já foi apagada da memória.
  • Lixo de Memória: Um ponteiro não inicializado contém um valor aleatório. Tentar usá-lo pode travar o sistema.
  • Inicialização Segura: Sempre inicialize ponteiros com NULL se não tiver um endereço para eles no momento.
int *ptr = NULL; // Prática Recomendada
